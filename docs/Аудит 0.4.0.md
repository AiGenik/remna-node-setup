# Аудит Remna Node Setup 0.4.0

21 ноября 2026. Проверены публичный выпуск v0.4.0 (`ccfd2b9`), установка и обновления, правила доступа, откат и диагностика. Сценарии выполнялись в отдельной Ubuntu 24.04 и на тестовых данных.

ShellCheck, штатные тесты и сборка прошли. Контрольная сумма публичного архива совпала с данными GitHub и `SHA256SUMS`. Распакованные файлы совпали с тегом. Отдельные проверки подтвердили ожидание занятой блокировки после срабатывания systemd и ложный успех двух проверок портов. [Сборка v0.4.0](https://github.com/AiGenik/remna-node-setup/actions/runs/44800085033)

## Следующие исправления

- **Достоверная диагностика.** Тестовые правила только для IPv6 проходят проверку без IPv4. При двух настроенных портах успешная проверка одного скрывает отсутствие второго. Неактивный TrafficGuard выводит предупреждение с кодом успеха. При отсутствующем конфиге self-steal проверка тоже может завершиться успешно. Разделить ожидаемые порты, сокеты, правила IPv4/IPv6 с учётом их порядка и внешнюю доступность. Добавить проверку DNS и таймера Certbot. [Порты](../lib/security.sh#L294) · [TrafficGuard](../lib/traffic-guard.sh#L249) · [Self-steal](../lib/selfsteal.sh#L190) · [Диагностика](../lib/manager.sh#L562)
- **Журнал сбойной установки.** После неудачного запуска ноды мастер направляет в «Логи», уже вернув предыдущий контейнер или удалив новый. Сохранять короткий фрагмент журнала до отката с маскированием ключа. [Запуск ноды](../lib/node.sh#L193) · [Восстановление контейнера](../lib/node.sh#L235)
- **Согласованность конфигурации.** При смене IP панели сверять его с активными наборами TrafficGuard. Сохранять явно выбранное «нет» как значение по Enter, даже если Xray начал слушать порт. При смене публичного порта обновлять сохранённое HTTPS-перенаправление, даже если веб-сервис временно не отвечает. [Правила](../lib/manager.sh#L372) · [Подсказка портов](../lib/security.sh#L79)
- **Снимки и восстановление.** Тестовая ошибка копирования оставила целевой файл удалённым. Готовить копию до замены файла и проверять её. Для «Только нода» включать внешний UFW в снимок по явному выбору. Добавить срок хранения автоматических снимков с сохранением активного снимка отката и ручных копий. [Восстановление файлов](../lib/transaction.sh#L28) · [Состав снимка](../lib/manager.sh#L515)
- **Предпросмотр обновлений.** В тесте выбор Nginx показывал только `nginx`, хотя APT также планировал обновить `nginx-common`. Показывать полный план APT и выбирать проверки служб по нему. Для первоначальной установки `jq` и `curl` применить ту же строгую политику проверки индексов и пакетов. [План APT](../lib/common.sh#L72) · [Начальный установщик](../install.sh#L278)
- **Подлинность выпуска.** У публичного v0.4.0 совпадают SHA-256 GitHub, файл контрольных сумм и содержимое тега. В API у релиза `immutable: false`. Для будущих выпусков включить неизменяемость и проверять аттестацию перед запуском полученного кода от root. Обычное обновление должно отдельно проверять, что найденный релиз новее установленного. Изолированный тест с более старым `latest` подтвердил понижение версии. [Обновление](../lib/release.sh#L16) · [Проверка релизов GitHub](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/verify-release-integrity)

## Что добавить

1. **Сводку состояния** с версиями пакетов, датой последней проверки и версией списка TrafficGuard, сроком сертификата и статусом его продления. Отдельные команды для просмотра доступных обновлений и применения помогут планировать перезапуски.
2. **Управляемые автообновления Ubuntu.** Отдельная опция настройки `unattended-upgrades` для исправлений безопасности и просмотр результата последнего запуска. Обновления Docker и изменения firewall подтверждаются отдельно. [Документация Ubuntu](https://ubuntu.com/server/docs/how-to/software/automatic-updates/)
3. **Альтернативный выпуск сертификата.** Оставить HTTP-01 для обычного VPS. Добавить DNS-01 по запросу для случаев, когда TCP 80 недоступен, и показать источник DNS-ответа при проверке. [Типы проверок Let's Encrypt](https://letsencrypt.org/docs/challenge-types/)
4. **Тесты до публикации.** Запускать текущие проверки на PR и добавить отдельную проверку на systemd для потери SSH, ошибки снимка, ошибки зеркала APT и обновления существующей установки. Сейчас workflow запускается при теге и включает тесты APT, портов и TrafficGuard через `standalone-settings.sh`. [Workflow выпуска](../.github/workflows/release.yml)
