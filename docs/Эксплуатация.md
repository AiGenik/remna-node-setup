# Эксплуатация

## Диагностика

```bash
sudo remna-node-setup status
sudo remna-node-setup doctor
sudo remna-node-setup logs
```

Мастер проверяет контейнер, локальные порты, Caddy и состояние защиты. Связь с панелью видна в самой панели. Быстро посмотреть причину проблемы с сертификатом можно через `sudo journalctl -u caddy -n 50`.

Если BBR выведен как недоступный, VPS использует ядро без нужного алгоритма или не разрешает загрузить модуль. Другие компоненты продолжают работать. `fq` задаётся как очередь по умолчанию для новых интерфейсов.

## Обновление

1. Сохраните снимок в меню или запустите `sudo remna-node-setup backup`.
2. Установите новый стабильный релиз скрипта через «Обновить скрипт» и заново откройте меню.
3. Выберите «Обновить ноду» или «Включить или обновить TrafficGuard». Версии берутся из манифеста установленного релиза. Обновление образа может прервать активные соединения.
4. После обновления TrafficGuard подтвердите сеть из второго SSH-сеанса.

В режиме `--local` репозиторий для обновлений задаётся при первом запуске GitHub-установщика с `OWNER/REPO`. `rollback tool` переключает только версию команды. Для возврата конфигурации компонентов восстановите снимок.

## Восстановление

Команда `sudo remna-node-setup rollback` отменяет текущее неподтверждённое сетевое изменение. По умолчанию таймер делает это через 10 минут после начала изменения. Он включён и при перезагрузке до подтверждения, в таком случае отсчёт запускается заново.

Сохранённые снимки находятся в `/var/backups/remna-node-setup`. Выберите «Восстановить снимок» в меню или выполните `sudo remna-node-setup restore ID`. Снимки содержат секрет ноды и доступны root. При восстановлении сетевых правил снова потребуется подтверждение SSH. Уже установленные системные пакеты, скачанные образы и ACME-данные Caddy остаются на VPS.

Если не удаётся войти по SSH, используйте консоль провайдера: `sudo remna-node-setup rollback`. Состояние таймера видно через `systemctl status remna-node-setup-rollback.timer`, журнал через `journalctl -u remna-node-setup-rollback.service`.
