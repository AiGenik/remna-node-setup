# Эксплуатация

## Диагностика

```bash
sudo remna-node-setup status
sudo remna-node-setup doctor
sudo remna-node-setup preflight
sudo remna-node-setup dns node.example.com
sudo remna-node-setup logs
```

Диагностика сверяет слушающие сокеты Xray с локальными правилами UFW и проверяет расписание автоматических обновлений Ubuntu. Доступ с клиентской сети проверяется отдельным подключением.

Если Xray слушает `9443/tcp`, выберите «Порты и защита → Входящие порты и защита SSH» и добавьте `9443/tcp`. Укажите тот же порт в Host. Подтвердите изменения из нового SSH-сеанса.

Проверка DNS показывает отсутствующую запись, ошибку резолвера или расхождение между A/AAAA и адресами VPS. При ошибке установки мастер показывает последние строки вывода операции перед восстановлением снимка.

Для смены веб-сервера откройте «Порты и защита → Настроить self-steal». Выберите Caddy или Nginx. Если скрипт менял правило UFW для HTTP-01, подтвердите изменение в новом SSH-сеансе. При ошибке возвращается предыдущая конфигурация. В профиле панели сохраняется адрес `127.0.0.1:8443`.

Журнал сертификатов Caddy доступен через `sudo journalctl -u caddy -n 50`. Для Nginx проверьте `sudo journalctl -u remna-node-setup-certbot.service -n 50` и журналы в `/var/lib/remna-node-setup/nginx-certbot/logs`.

Если BBR выведен как недоступный, VPS использует ядро без нужного алгоритма или не разрешает загрузить модуль. Другие компоненты продолжают работать. `fq` задаётся как очередь по умолчанию для новых интерфейсов.

### Проверка связи до установки

В общей установке проверка идёт после выбора портов и до запуска установки. Отдельно она открывается в «Диагностика → Проверить связь до установки» или через `sudo remna-node-setup preflight`. Сверьте `NODE_PORT` с карточкой ноды и укажите порты VPN из профиля. Для новой ноды отдельная проверка предлагает `443/tcp` и `9443/tcp`. Для `8443/tcp` self-steal и UDP проверяется локальная занятость.

После запуска внешнего теста оставьте мастер открытым и вставьте показанную команду в терминал сервера панели. В течение 90 секунд свободные TCP-порты принимают тестовые данные от указанных IP панели. Результат подтверждается после получения всех данных и ответа. Сокеты закрываются после проверки. Правила UFW и firewall провайдера действуют во время теста. При ошибке проверьте адрес, разрешённый исходящий IP и сетевой путь. Для работающей ноды мастер показывает команду проверки её TLS.

Успешный обмен подтверждает TCP с сервера панели при текущих сетевых правилах. Конфигурация Remnawave, ключ, клиентский доступ и выпуск сертификата проверяются после установки.

## Обновление

В меню «Обновления → Обновить всё» мастер проверяет скрипт и обновляет установленные компоненты. Это включает пакеты, ноду, базу TrafficGuard и управляемый Psiphon. Изменения firewall требуют одного подтверждения через новое SSH-подключение.

```bash
sudo remna-node-setup update all
```

### Автообновления

Откройте «Обновления → Автообновления» и подтвердите включение. Проверка запускается ежедневно около 04:00 по времени VPS. Службы могут перезапускаться.

Пакеты, затрагивающие firewall, проходят через ручное «Обновить всё». Фоновое обновление TrafficGuard меняет базу при наличии сохранённого доверенного IP SSH и проверяет общие правила firewall. Если проверка не проходит, мастер восстанавливает снимок.

```bash
sudo remna-node-setup auto-updates status
sudo journalctl -u remna-node-setup-auto-update.service -n 60
```

### Обновление по частям

1. Сохраните снимок в меню или запустите `sudo remna-node-setup backup`.
2. Установите новый стабильный релиз скрипта через «Обновить скрипт» и заново откройте меню.
3. Для Nginx, Caddy, Certbot, UFW, Fail2Ban и Docker выберите «Обновить системные пакеты». Мастер обновит индексы APT и покажет версии установленных пакетов и доступные обновления. Изменения применяются после подтверждения. При обновлении службы могут перезапуститься.
4. Выберите «Обновить TrafficGuard», чтобы скачать текущий стабильный релиз и список сканеров. После применения подтвердите сеть из нового SSH-сеанса.
5. Сначала обновите панель Remnawave. Затем выберите «Обновить ноду», чтобы скачать свежий стабильный образ. Замена контейнера может прервать соединения. [Порядок обновления Remnawave](https://docs.rw/install/upgrading/)

Для обновления конкретного пакета выполните, например, `sudo remna-node-setup update packages nginx`. APT сохраняет существующие конфигурационные файлы. Пакеты с `apt-mark hold` пропускаются с сообщением. После обновления активный Nginx проходит проверку конфигурации и перезапускается. [Исправления для Nginx в Ubuntu 24.04](https://ubuntu.com/security/notices/USN-9182-1)

В режиме `--local` репозиторий для обновлений задаётся при первом запуске GitHub-установщика с `OWNER/REPO`. `rollback tool` переключает только версию команды. Для возврата конфигурации компонентов восстановите снимок.

## Восстановление

Команда `sudo remna-node-setup rollback` отменяет текущее неподтверждённое сетевое изменение. Красное предупреждение показывает время до автоотката при открытии экрана. Таймер запускается на 10 минут с начала изменения. Если сервер перезагрузится до подтверждения, отсчёт начнётся заново.

Сохранённые снимки находятся в `/var/backups/remna-node-setup`. Выберите «Восстановить снимок» в меню или выполните `sudo remna-node-setup restore ID`. Снимки содержат секрет ноды и доступны root. При восстановлении сетевых правил снова потребуется подтверждение SSH. Установленные пакеты, скачанные образы и данные сертификатов остаются на VPS.

Если не удаётся войти по SSH, используйте консоль провайдера: `sudo remna-node-setup rollback`. Состояние таймера видно через `systemctl status remna-node-setup-rollback.timer`, журнал через `journalctl -u remna-node-setup-rollback.service`.
