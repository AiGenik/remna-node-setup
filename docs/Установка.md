# Установка

## Подготовка

- Отдельный VPS с Ubuntu 24.04 и systemd, архитектура amd64 или arm64.
- Домен или публичный IP ноды. Для self-steal нужен домен. Направьте A и используемые AAAA-записи на публичные адреса VPS. В Cloudflare включите DNS only.
- В панели откройте «Ноды → Управление → +» и заполните карточку. Мастер подскажет поля и покажет примеры. [Инструкция Remnawave](https://docs.rw/install/remnawave-node/)
- Держите открытым текущий SSH-сеанс и убедитесь, что доступна консоль VPS.

## Мастер

1. В Терминале на компьютере подключитесь к VPS по SSH. В открывшемся сеансе вставьте команду установки мастера. Меню откроется в том же сеансе. [Команды по порядку](../README.md#быстрый-старт)
2. Выберите **[1] Всё под ключ** (полная настройка новой ноды за один проход: нода, Nginx self-steal, BBR, отключение IPv6, UFW, Fail2Ban `DROP`, TrafficGuard, Psiphon и автообновления) или **[2] Установка и настройка по частям → [1] Установить только ноду** для базовой установки. Для автоматической проверки связи с панели откройте меню через помощник на компьютере. [Установка помощника](../README.md#помощник-remna-ssh)
3. При запуске через `remna-ssh --panel` нажмите Enter на шаге проверки. Помощник сам запустит тест с панели. При прямом запуске мастера на VPS доступна ручная проверка. [Проверка связи](Эксплуатация.md#проверка-связи-до-установки)
4. Проверьте настройки и введите `y` для установки. `n` отменяет действие. Enter выбирает заглавную букву.
5. После изменений firewall нажмите Enter в `remna-ssh`. При прямом запуске откройте новый SSH-сеанс и выполните `sudo remna-node-setup confirm`. До подтверждения держите исходный сеанс открытым. [Порядок подтверждения](Эксплуатация.md#подтверждение-ssh)

Мастер берёт стабильный образ ноды с Docker Hub. Для системных пакетов используются подписанные репозитории APT, для TrafficGuard — стабильный релиз и официальный список сканеров.

Если APT занят, мастер проверяет его каждые 5 секунд и ждёт до 10 минут. Когда блокировка снимается, установка продолжается автоматически. Если время вышло, дождитесь завершения системных обновлений и запустите установку снова.

Если проверка self-steal остановилась, исправьте DNS и повторите проверку, смените домен или установите ноду и вернитесь к self-steal позже. Введённые поля сохраняются в текущем сеансе мастера. Отдельная проверка доступна в «Диагностика → Проверить DNS домена» и через `sudo remna-node-setup dns node.example.com`.

## Что вводить

| Что запросит мастер | Где взять | Зачем |
| --- | --- | --- |
| `NODE_PORT` | `Node Port` в карточке ноды или `NODE_PORT` в скачанном Compose. | По этому порту панель управляет нодой. |
| `SECRET_KEY` | `Secret Key` в карточке ноды или `SECRET_KEY` в Compose. После вставки нажмите Enter. | Ключ для связи панели с нодой. |
| Домен self-steal | Домен, чьи записи A и используемые AAAA указывают на этот VPS. | Для сайта и TLS-сертификата, если включён self-steal. |
| IP панели | На сервере панели выполните `curl -4fsS https://api.ipify.org && echo`. Если адресов несколько, разделите их пробелами. | UFW разрешит панели доступ к служебному порту ноды. |
| Порт SSH | Мастер предлагает порт текущего соединения. | Чтобы сохранить доступ к VPS после настройки firewall. |
| Клиентские порты | Remnawave → Config Profiles → профиль ноды → `inbounds` → `port`. Пример формата `9443/tcp 2443/udp`. | По ним подключаются VPN-клиенты. |

## Какие порты открывать

| Назначение | Правило |
| --- | --- |
| SSH | Действующий порт SSH по TCP. |
| Связь панели с нодой | `NODE_PORT/tcp` только с исходящих IP панели. |
| Подключения клиентов и дополнительные сервисы | Подтверждённые порты со своим протоколом, например `9443/tcp 2443/udp`. Укажите «нет», чтобы оставить служебные правила. |
| Выдача и продление сертификата self-steal | `80/tcp` при HTTP-01. Локальный HTTPS на `127.0.0.1:8443` доступен Xray внутри VPS. |

Мастер показывает найденные публичные сокеты Xray. Для новой ноды, которая ещё не получила профиль, возьмите порты из панели. При self-steal укажите порт VLESS REALITY первым среди TCP-портов. Мастер использует его для HTTPS-перенаправления. Сверьте правила firewall у провайдера, проверьте статус ноды в панели и подключитесь тестовым клиентом. [Config Profiles](https://docs.rw/learn-en/config-profiles/) · [Настройка порта Host](https://docs.rw/learn-en/hosts/#specify-a-port)

## Установка по частям

В меню «Порты и защита» можно отдельно настроить self-steal, BBR, отключение/включение IPv6 (`sudo remna-node-setup ipv6 [disable|enable|status]`) и TrafficGuard. Для Nginx self-steal изолирует прямые обращения по IP-адресу (`444`/`204`), отдаёт статическую заглушку Kestrel Systems только по имени домена и продлевает TLS-сертификат через Certbot (`webroot`) с автоперезагрузкой Nginx. Fail2Ban настраивается на немедленный сброс пакетов (`banaction = iptables-multiport[blocktype=DROP]`), а для автозапуска UFW включаются и `ufw.service`, и `ENABLED=yes` в `/etc/ufw/ufw.conf`. После смены профиля Xray откройте «Входящие порты и защита SSH» и проверьте список. Для TrafficGuard нужен включённый UFW.

## Существующая нода

При обнаружении сторонней установки мастер остановится. Откройте статус текущей ноды в панели и сохраните её Compose, ключ и веб-конфигурацию. Для перехода установите новую ноду на отдельном VPS, проверьте подключение тестового клиента, затем переведите нужный хост в панели на новую ноду. Сохраняйте старую ноду до проверки перехода.
