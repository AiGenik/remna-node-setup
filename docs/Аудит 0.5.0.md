# Аудит Remna Node Setup 0.5.0

21 ноября 2026. Проверка продолжает [аудит 0.4.0](Аудит%200.4.0.md). Она охватывает код установщика, источники пакетов и образа, SSH, UFW, сетевой откат и диагностику.

На Ubuntu 24.04 прошли ShellCheck, тесты, обе установки с официальным образом и восстановление снимка. В лаборатории с OpenSSH подтверждение из транспорта, открытого заранее, было отклонено. Новое соединение прошло. В регрессиях ошибка чтения UFW остановила изменение, ошибка копирования сохранила рабочий файл, а восстановление после таймаута началось после завершения рабочих процессов.

## Изменения по аудиту

- Снимок сети требует достоверного состояния UFW. Восстановление готовит копию файла до замены. При работе с внешними правилами мастер сохраняет существующую политику SSH и останавливается, если её нельзя безопасно перенести.
- Изменение сети ограничено по времени. Перед восстановлением мастер завершает применяющие процессы. Служба systemd повторяет попытку отката, если блокировка ещё занята. Подтверждение по SSH проверяет время запуска транспорта относительно окончания операции. Новая вкладка в старом соединении подтверждение не пройдёт.
- Диагностика проверяет локальные сокеты и правила UFW, ожидаемую ноду, TrafficGuard, DNS и таймер Certbot. Снимок режима «Только нода» без управляемой защиты исключает внешний UFW.
- По умолчанию обновление скрипта блокирует понижение версии. Установщик проверяет SHA-256 архива по метаданным GitHub, ограничивает типы файлов в архиве и проверяет комплект до активации. Изначальная установка утилит требует успешного обновления индексов подписанных репозиториев APT.
- Для ноды выбирается стабильный релиз Remnawave и проверяется SHA-256 манифеста Docker Hub. Образ в Compose и снимке остаётся привязан к точному digest. TrafficGuard использует текущий стабильный релиз и официальный список. [Источники образа Remnawave](https://github.com/remnawave/node/releases) · [Порядок обновления панели и ноды](https://docs.rw/install/upgrading/)

## Что проверить и улучшить в следующем выпуске

1. Показывать полный план APT с зависимостями и связывать с ним перезапуск служб.
2. Учитывать семейство адресов и порядок правил UFW. Сейчас правило IPv6 может пройти проверку для IPv4. Отдельно проверять доступность снаружи, поскольку локальные данные не показывают фильтрацию у провайдера.
3. Закрепить неизменяемость будущих выпусков GitHub и включить проверку аттестации до запуска от root. Сейчас архив доверяет SHA-256 из самого публичного релиза GitHub. [Проверка релизов GitHub](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/verify-release-integrity)
4. Добавить срок хранения автоматических снимков и отчёт о последнем успешном обновлении и продлении сертификата.
