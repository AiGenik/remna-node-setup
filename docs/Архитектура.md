# Архитектура

- Команда `remna-node-setup` загружает модули из `lib/`. Меню и CLI используют одинаковые операции. Пункты находятся в `MENU_ACTIONS` в `lib/ui.sh`, команды выполняет диспетчер в `lib/manager.sh`. В интерактивном терминале экран перерисовывается при переходах.
- Версии кода размещаются в `/opt/remna-node-setup/releases`. Установщик сверяет SHA-256 архива через метаданные публичного GitHub-релиза и переключает текущую версию после самопроверки.
- Состояние ноды хранится в `/etc/remna-node-setup`, Compose в `/opt/remna-node-setup-node`. Стабильный тег определяется через официальный GitHub Remnawave. SHA-256 из Docker Hub сверяется с полученным манифестом. Compose и снимки используют точный OCI digest. Docker использует host network и ограничивает размер журналов контейнера.
- Настройки компонентов до установки ноды хранятся в `/etc/remna-node-setup/host.json`. При установке ноды мастер переносит их в `node.json`. Снимок сохраняет оба файла. Минимальный режим меняет конфигурацию ноды и контейнер, без сетевой транзакции.
- Изменения сериализуются файловой блокировкой. Снимок хранит затронутые конфиги и состояние сервисов. Перед изменением сетевых правил запускается таймер systemd, а при ошибке скрипт сразу пробует восстановить снимок.
- `remna-ssh` открывает меню через OpenSSH с компьютера администратора. После применения управляющая команда сохраняет одноразовый идентификатор вместе со снимком. Второй SSH-транспорт должен быть новее отметки применения и подтвердить этот снимок под той же блокировкой. При отказе таймер продолжает отсчёт.
- При сетевом откате контейнер с изменённым служебным портом останавливается перед восстановлением прежнего firewall. Новые снимки сохраняют состояние контейнера, в том числе если нода была остановлена.
- Клиентские порты хранятся в `vpn_ports` с протоколом. Старый `node.json` читается с TCP 443. Сокеты Xray используются как предложения, а правила UFW берутся из согласованного списка. При изменении сетевых правил снимок сохраняет предыдущую конфигурацию.
- Caddy и Nginx используют TCP 80 для ACME HTTP-01 и loopback TCP 8443 для HTTPS. HTTP-перенаправление использует первый подтверждённый TCP-порт клиентов. Вариант с Nginx продлевает сертификат отдельным таймером Certbot. Снимок сохраняет конфиги и состояния обоих серверов.
- TrafficGuard сверяет SHA-256 бинарника текущего стабильного релиза с данными GitHub. Список загружается по проверенному Git-коммиту и сверяется по хешу содержимого. До применения проверяются пересечения IPv4/IPv6 с адресами панели и администратора, после — загруженные наборы и связка с UFW. BBR и `fq` применяются через отдельный файл sysctl.
- «Обновить всё» сначала проверяет новую версию мастера, затем продолжает работу с ней под той же блокировкой. APT моделирует изменения с зависимостями. Ручное обновление объединяет пакетные изменения firewall и TrafficGuard в одну сетевую операцию. В фоновом режиме TrafficGuard сравнивает правила до и после применения.
- Таймер systemd запускает ночное обновление после явного включения. Psiphon хранит параметры управляемого экземпляра отдельно, проверяет публикацию SOCKS5 на loopback и восстанавливает конфигурацию при сбое.
