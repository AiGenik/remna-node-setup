# Архитектура

- Команда `remna-node-setup` загружает модули из `lib/`. Меню и CLI используют одинаковые операции. Пункты находятся в `MENU_ACTIONS` в `lib/ui.sh`, команды выполняет диспетчер в `lib/manager.sh`. В интерактивном терминале экран перерисовывается при переходах.
- Версии кода размещаются в `/opt/remna-node-setup/releases`. Установщик сверяет SHA-256 архива через метаданные публичного GitHub-релиза и переключает текущую версию после самопроверки.
- Состояние ноды хранится в `/etc/remna-node-setup`, Compose в `/opt/remna-node-setup-node`. Образ ноды закреплён по OCI digest. Docker использует host network. Ограничения UFW применяются к входящим соединениям ноды, а Docker ограничивает размер и число файлов журналов контейнера.
- Изменения сериализуются файловой блокировкой. Снимок хранит затронутые конфиги и состояние сервисов. Перед изменением сетевых правил запускается таймер systemd, а при ошибке скрипт сразу пробует восстановить снимок.
- Caddy и Nginx используют TCP 80 для ACME HTTP-01 и loopback TCP 8443 для HTTPS. TCP 443 принадлежит Xray. Вариант с Nginx продлевает сертификат отдельным таймером Certbot. Снимок сохраняет конфиги и состояния обоих серверов.
- TrafficGuard скачивается из закреплённого релиза и сверяет SHA-256. Список также закреплён по коммиту и контрольной сумме. До применения проверяются пересечения IPv4/IPv6, после — загруженные наборы и связка с UFW. BBR и `fq` применяются через отдельный файл sysctl.
