# Журнал разработки

## 2026-11-20

- Утверждена первая версия для Ubuntu 24.04. Ноду регистрирует администратор в существующей панели.
- Заведено хранилище документации проекта. Следующие этапы — мастер, защита, релизы и проверки.
- Реализованы мастер, единое меню и CLI. Добавлены установка ноды и Caddy, UFW, Fail2Ban, TrafficGuard, BBR, диагностика, снимки, обновления и откат.
- На тестовой Ubuntu 24.04 ARM64 прошли проверки сборки релиза, SHA-256, блокировки параллельных операций, обновления и возврата предыдущего релиза.
- Проверены реальный SSH на TCP 2202, блокировка Fail2Ban после неудачных входов, доступ к порту панели по IPv4/IPv6 и сохранение UFW/TrafficGuard после перезагрузки. Проверены откат чистой установки TrafficGuard и возврат прежнего списка.
- Конфигурации Caddy и Compose прошли проверку. Ядро тестовой машины не предоставляет BBR и `fq`, скрипт корректно пропускает настройку. Выпуск публичного сертификата и тест клиента требуют домен и работающую панель.
- Сквозной тест в изолированной Ubuntu установил официальный образ ноды с тестовым ключом. Повторный запуск сохранил ключ, текущий SSH-сеанс не смог подтвердить изменения, новое подключение подтвердило их. Служебный порт принимал соединения только от разрешённого адреса.
- При ошибке запуска с недействительным ключом восстановились прежний ключ и рабочий контейнер. Отдельно проверен обработчик таймера systemd и восстановление сетевого снимка.
- После перезагрузки тестовой Ubuntu контейнер автоматически запустился с сохранённой конфигурацией. Сторонняя нода распознана до применения настроек.
- Релиз 0.1.0 собран GitHub Actions. В 0.1.1 мастер сохраняет прежний SSH-порт при повторном запуске из локальной консоли или через loopback.
- GitHub Actions опубликовал 0.1.1. На Ubuntu проверены установка из публичного релиза, обновление 0.1.0 → 0.1.1, возврат на 0.1.0, повторное обновление, работа ноды и сохранение SSH-порта 2202. [Сборка 0.1.1](https://github.com/AiGenik/remna-node-setup/actions/runs/44773188584)

## Интерфейс 0.1.2

- Меню разбито на разделы. В SSH-терминале каждый переход заменяет предыдущий экран. Результат операции остаётся видимым до Enter.
- Мастер показывает источник, формат и пример каждого поля. Названия сверены с интерфейсом панели Remnawave. Порт и ключ можно вставить целой строкой из Compose.
- В псевдотерминале Ubuntu проверены смена экранов, возврат, повтор ввода после ошибки и скрытый ключ. Проверен ввод через pipe без управляющих кодов.

## Интерфейс и веб-сервер 0.1.3

- В Ubuntu воспроизведено усечение длинной строки до 4095 символов в старом скрытом вводе. Новый ввод принимает 7200 символов целиком, показывает их количество и восстанавливает настройки терминала. Проверена вставка ключа и строки Compose.
- Возвращены подсказки `[Y/n]` и `[y/N]`. Заголовки и поля выделены жирным, текст мастера сокращён.
- Self-steal поддерживает Caddy и Nginx. Старые конфигурации читаются как Caddy. На Ubuntu проверены переключение, откат, HTTP-01 с тестовым ответом, loopback TLS и таймер Certbot. Публичная выдача сертификата проверяется на рабочем домене.

## Интерфейс, диагностика и установка по частям 0.2.0

- Добавлены фирменный заголовок, навигация, шкала шагов и компактный режим. Долгие операции показывают состояние, а при ошибке выводят последние строки журнала.
- DNS-проверка различает отсутствие записи, сбой резолвера и расхождение с адресами VPS. Исправление домена и пропуск self-steal доступны внутри мастера. Учтены пустые записи в JSON-выводе iproute2.
- BBR, UFW с Fail2Ban, TrafficGuard и Caddy/Nginx настраиваются до установки ноды. Для ноды есть отдельный режим, который переносит сохранённые параметры сервера.
- На выделенном VPS с Ubuntu 24.04 amd64 проверены SSH-интерфейс, ошибка DNS и возврат к установке. Caddy и Nginx получили доверенные сертификаты для тестового домена. Проверены отдельная настройка BBR с fq, UFW, Fail2Ban, TrafficGuard и подтверждение нового SSH-сеанса.
- При занятом dpkg блокировка больше не прерывает установку сразу. В ходе проверки после ошибки установки Caddy вернулись Nginx и таймер Certbot.
- На том же VPS установлена нода поверх отдельных компонентов. Снаружи проверены mTLS и запрос тестовой панели, HTTPS self-steal через порт 443 и запрос VLESS-клиента. Отдельный сетевой адрес получил отказ на служебном порту. Пробное продление Certbot прошло.
- Проверено обновление VPS на опубликованный 0.2.0. После срабатывания службы отката файлы настроек ноды и UFW совпали со снимком по SHA-256. Тестовая нода, ключи в активной конфигурации и правила сняты. Скрипт оставлен готовым к настройке пользователя. [Сборка 0.2.0](https://github.com/AiGenik/remna-node-setup/actions/runs/44786069496)

## Выбор входящих портов и оформление «Сеть» 0.3.0

- На пользовательском VPS Xray слушал TCP 9443, а управляемое правило UFW разрешало TCP 443. В мастере добавлен список TCP/UDP с подсказкой по локальным сокетам Xray. Применяются подтверждённые порты. Служебный порт сохраняет ограничение по IP панели.
- Выбран вариант «Сеть». Главное меню разделено на установку и управление. «Только нода» стоит первым пунктом. Шкала показывает выполненные этапы, текущую операцию и предстоящие этапы. При сбое видны этап и последние строки журнала.
- На изолированной Ubuntu 24.04 проверены установка реальной ноды без пакетов защиты, последующая настройка UFW с `9443/tcp` и `2443/udp`, откат и возврат минимальной конфигурации. С отдельных сетевых адресов проверены доступ к клиентским портам и ограничение служебного порта.
- Тесты также покрывают чтение старой конфигурации, перенос HTTPS-перенаправления Caddy и Nginx на выбранный TCP-порт, защиту существующих правил, подсказки и скрытый ввод ключа. Сборка пакета и контрольная сумма проверены.
